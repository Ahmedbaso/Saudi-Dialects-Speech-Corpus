Saudi Dialects Speech Corpus

A graduation project focused on building a structured Saudi dialect speech corpus using an automated Telegram Bot for voice data collection, processing, and storage.

Project Overview

This project aims to build a Saudi dialect speech corpus by collecting voice recordings from participants across different Saudi dialect regions. The system uses a Telegram Bot to guide participants through privacy approval, demographic questions, dialect information, and voice recording steps.

Problem Statement

Arabic speech recognition systems often face challenges when processing regional dialects, especially spontaneous Saudi dialects. This project addresses the lack of structured, phonetically balanced, and regionally diverse Saudi speech datasets.

Telegram Bot Workflow

  1. The participant starts the bot using /start.
  2. The bot displays the privacy policy and requires explicit consent.
  3. The bot collects participant metadata such as age, gender, dialect region, education level, and device type.
  4. The bot displays a recording notice asking the participant to remove headphones and record directly using the phone microphone.
  5. The participant records 30 predefined phonetically balanced sentences.
  6. For each sentence, the participant can approve the recording or re-record it.
  7. The participant may optionally record a free-speech sample or skip this step.
  8. The bot shows a final confirmation button before processing and uploading the files.
  9. After final confirmation, the audio files are processed, renamed, compressed, uploaded, and stored.

System Workflow

Participant ↓ Telegram Bot ↓ Voice Note in OGG Format ↓ Temporary OGG Storage in data/tmp ↓ FFmpeg Audio Processing ↓ Standardized WAV File ↓ File Renaming ↓ ZIP Archive + info.txt ↓ Local Storage + Cloudinary + Airtable

Audio Processing

Telegram voice notes are received in OGG format. The backend uses Python and FFmpeg to convert each recording into a standardized WAV file.

  • WAV format
  • 44.1kHz sample rate
  • Mono channel
  • PCM 16-bit encoding

Recording Duration Rules

  • Each predefined sentence has a maximum recording duration of 15 seconds.
  • The optional free-speech recording has a technical maximum duration of 35 seconds.
  • If the participant exceeds the allowed duration, the bot asks them to re-record.

Storage Architecture

The system uses a triple-storage approach:

  • Local Storage: stores the generated ZIP archive and metadata file.
  • Cloudinary: stores uploaded audio files for cloud accessibility.
  • Airtable: stores participant metadata and recording references.

File Naming Convention

Each audio file follows a structured naming format designed to encode the dialect, speaker identity, sentence number, device type, and recording attempt directly in the filename.

KSU_DIA_D[Dialect_Code]_SPK[Gender_Digit][Speaker_ID]_S[Sentence_ID]_T[Device_Code][Attempt_Counter].wav

Example:

KSU_DIA_D01_SPK10023_S05_T11.wav

Part Meaning Example
KSU_DIA Project prefix for the Saudi Dialects Speech Corpus. KSU_DIA
D[Dialect_Code] Dialect region code assigned to the participant's dialect classification. D01
SPK[Gender_Digit][Speaker_ID] Speaker identifier. The first digit after SPK represents gender:
1 = Male
0 = Female
The remaining digits represent the speaker ID. 		SPK10023
Gender = 1, Speaker ID = 0023
S[Sentence_ID] Sentence number recorded by the participant. S05 = sentence 5
T[Device_Code][Attempt_Counter] Device and attempt code. The first digit after T represents device type:
1 = iPhone
0 = Android
The second digit represents the recording attempt number, with a maximum of 3 attempts. 		T11
Device = iPhone, Attempt = 1

Based on the example KSU_DIA_D01_SPK10023_S05_T11.wav, the file belongs to dialect code D01, a male speaker with ID 0023, sentence number 05, recorded using an iPhone on the first attempt.

Additional examples:

  • SPK00023: female speaker, speaker ID 0023.
  • SPK10023: male speaker, speaker ID 0023.
  • T01: Android, first attempt.
  • T03: Android, third attempt.
  • T11: iPhone, first attempt.
  • T13: iPhone, third attempt.

Privacy and Consent

The bot displays the privacy policy before collecting participant data. Participants must explicitly agree before continuing. The system avoids collecting phone numbers and allows participants to use a nickname or pseudonym.

Participants can cancel before the final upload confirmation. Once the final upload process starts, the submission is considered approved and cancellation is disabled inside the bot.
